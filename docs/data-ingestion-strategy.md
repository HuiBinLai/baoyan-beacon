# 保研灯塔数据采集与覆盖策略

## 目标

保研信息无法通过单一搜索引擎做到绝对全量。项目采用“源图谱 + 多通道发现 + 增量归档 + 覆盖率审计”的方式，把遗漏变成可发现、可补救、可追责的问题。

## 覆盖层级

1. 院校层：985、211、双一流高校的研究生院、研招办、教务处、招生专题页。
2. 学院层：每所学校的学院公告页、研究生招生页、通知公告页。
3. 公众号层：学校、研究生院、学院、学生组织和项目组公众号。
4. UGC 层：用户提交官网链接、公众号链接、面经、门槛、笔试/机试题型。

## 微信公众号方案

微信没有面向全网公众号文章的稳定官方公开搜索 API。官方公众号接口更适合获取“自己有权限管理的公众号”的素材列表，不适合直接拉取所有高校公众号。

因此项目采用三种方式叠加：

1. 白名单公众号监测：为每个学校/学院登记公众号名称、微信号、历史文章链接、搜索关键词。
2. 每日搜索补漏：按“学校 + 学院 + 推免/夏令营/预推免/直博 + 日期”查询微信网页结果、搜狗微信、通用搜索引擎和第三方文章检索服务。
3. 用户投稿兜底：任何用户看到公众号通知，可以提交文章链接；系统只保存标题、摘要、结构化字段和原文链接，不全文搬运。

## LLM 入库流程

每条候选链接进入数据库前经过以下步骤：

1. 抓取标题、发布时间、正文片段、来源 URL、来源类型。
2. 规则过滤：排除考研机构、广告、名单公示、登录页、无关招聘等。
3. LLM 结构化：抽取学校、学院、专业、年份、通知阶段、培养类型、报名时间、截止时间、申请条件、材料要求、报名方式。
4. 置信度标记：`auto` 表示自动入库，`verified` 表示人工核验。
5. 去重与变更检测：按 URL、规范化标题、内容 hash 判断新增、重复、更新。

## 每日增量判断

每个 source 需要保存：

- `lastCheckedAt`：最后检查时间。
- `lastSuccessAt`：最后成功抓取时间。
- `lastNewItemAt`：最后发现新通知时间。
- `lastHash`：列表页或文章页内容 hash。
- `lastStatus`：成功、无变化、抓取失败、结构化失败、疑似反爬。
- `itemCount`：该源累计入库条数。

每日任务输出覆盖率报告：

- 哪些学校今天有新增。
- 哪些学院源今天内容变化但未识别出通知。
- 哪些源抓取失败。
- 哪些学校/学院近五年仍为空。
- 哪些新增候选需要人工核验。

## 211/双一流扩展路线

教育部第二轮“双一流”建设高校共 147 所，且不再区分一流大学建设高校和一流学科建设高校。项目扩展时以“双一流 147 所”为主清单，同时标记 985/211 身份，避免维护两套重复源。

建议分三批推进：

1. 第一批：985 已有基础，补齐学院源和公众号源。
2. 第二批：非 985 的 211/双一流中推免需求高的院校，例如两财一贸、法大、北邮、北交、华东理工、南航、南理工、苏大、暨大等。
3. 第三批：剩余双一流高校按省份和学科强相关度补齐。

## 用户需要做的人工工作

早期最需要人工做的是“源确认”，不是逐条搬运通知：

1. 每所学校确认研究生院/研招办入口。
2. 每个学院确认公告页和研究生招生页。
3. 收集学院官方公众号名称/微信号。
4. 对自动入库的高价值通知抽查并标记 `verified`。

这部分可以众包：网站后台显示“缺源学院”和“待核验条目”，用户认领补充。
